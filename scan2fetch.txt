1. WHAT THE SYSTEM DOES
================================================================================

Scan2Fetch is the gate-side release and pickup monitoring system for the school.
Every learner has a record, every guardian (and sub-fetcher) carries a QR code,
and every hand-over is written to a log containing:

  - the student
  - the person who fetched the child (name + relation)
  - the guardian account behind that QR code (Parent ID + phone)
  - the staff member who released the child
  - the exact date and time
  - the session: MORNING or AFTERNOON
  - the method (QR)

The system answers four questions at any moment:

  1. Who is still inside the campus?        -> Scan Monitor
  2. Who picked up the child?               -> Pickup History
  3. When was the child released?           -> Pickup History / Teacher roster
  4. Who released the child?                -> Pickup History / Activity Logs

Parents receive an SMS the moment a child is released. Every action (login,
create, update, delete, release, decline) is stored in the Activity Logs so any
record can be audited later.

2. REQUIREMENTS
================================================================================

  - PHP 8.1 or newer (tested on PHP 8.2.12, XAMPP build)
  - MySQL 5.7+ / MariaDB 10.4+
  - Apache with mod_rewrite enabled (or `php spark serve` for development)
  - PHP extensions: intl, mbstring, mysqli/pdo_mysql, json, curl
  - Composer (only needed to reinstall dependencies)
  - A camera-capable device for the gate scanner (tablet or laptop)
  - SMS gateway configured on the server (local SMS bridge / HTTP gateway)

3. INSTALLATION AND SETUP
================================================================================

  1) Copy the project into the web root, e.g. C:\xampp\htdocs\scan2fetch
  2) Create the database:
         CREATE DATABASE scan2fetch CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
  3) Import the schema (students, parents, student_parents, sub_fetchers,
     teachers, staffs, fetch_logs, activity_logs, sms_logs, schedule, ...)
  4) Copy .env.example to .env and set:

         CI_ENVIRONMENT = development      (use "production" on the live server)

         database.default.hostname = localhost
         database.default.database = scan2fetch
         database.default.username = root
         database.default.password =
         database.default.DBDriver = MySQLi

         app.baseURL = 'http://localhost/scan2fetch/'

  5) Make sure these folders are writable:
         writable/
         writable/session/
         writable/cache/
         writable/logs/
         public/uploads/qr/
         public/uploads/students/
         public/uploads/parents/

  6) Open the base URL. Log in with the administrator account created during
     seeding (default seed: phone "admin", password set in the seeder).

  7) Enrol the first students (form or Excel import), then open the gate.

Apache shortcut:
    http://localhost/scan2fetch/         (document root = htdocs)

Development shortcut:
    php spark serve --port 8080

5. USER ROLES AND PERMISSIONS
================================================================================

ADMIN
  - Full access: students, parents, teachers, staff, scanning, monitor,
    schedule, logs, SMS logs, messages
  - Can open/close the day and switch sessions
  - Can delete records and "delete all" a module

STAFF
  - Operates the gate: scan, release, decline, kiosk
  - Students and parents management (add, edit, import, view)
  - Scan monitor and reminder SMS
  - Activity logs and SMS logs
  - Cannot manage the schedule

TEACHER
  - "My Students" roster for their own grade/section
  - Morning/Afternoon release status per student, per selected date
  - Pickup notifications for the class

PARENT
  - Own children, their pickup history and release records
  - Sub-fetchers management
  - Notifications
  - Chat with the office (Messages)

Role is enforced server-side on every request (AuthFilter + per-method checks).
The sidebar shows only the modules the account may open.

6. ID FORMATS
================================================================================

  Record           Format        Example     Entered at
  ---------------  ------------  ----------  ----------------------------------
  Student          number        1001        Excel import (col J) or form
  Parent / Guardian P-####       P-1001      Excel import (col K) or form
  Teacher          T-####        T-1001      form (blank = auto next)
  Staff            S-####        S-1002      form (blank = auto next)

Rules:
  - IDs are unique. A duplicate is rejected with an error message.
  - Left blank, the Teacher / Staff form assigns the next free number
    (T-1001, T-1002 ... / S-1001, S-1002 ...).
  - The ID is what gets printed on the QR code and typed at the counter.

================================================================================
8. DAILY WORKFLOW
================================================================================

  1. Admin opens the day        -> Schedule: open day, confirm both windows
  2. Gate staff open the scanner-> Scan or Kiosk, logged in with their account
  3. Guardian presents QR code  -> scanner resolves the child and guardians
  4. Staff confirm the release  -> system stamps date/time/session/staff,
                                   writes the log, sends the SMS
  5. Monitoring                 -> Scan Monitor shows who is still inside;
                                   teacher roster shows MORNING / AFTERNOON
                                   status per student for the chosen date
  6. End of day                 -> Admin closes the day; records, SMS and
                                   activity logs stay available for audit

================================================================================
9. SESSIONS AND RELEASE RULES
================================================================================

  - Two sessions per day: MORNING and AFTERNOON
  - Every release is tagged with the session active at scan time
  - One release per session: a child cannot be released twice in the same
    session; the second attempt is blocked with a message
  - Time windows: releases are only allowed inside the configured window;
    outside it the scanner refuses until an admin opens the day or switches
    the session manually
  - The pickup history reports the session exactly as recorded in the log
    (e.g. a 12:41 PM scan that the scanner resolved as MORNING stays MORNING)

================================================================================
10. SMS AND NOTIFICATIONS
================================================================================

  - Release SMS   : "Your child <name> has been released at <time>."
  - Decline SMS   : the guardian is told the pickup attempt was refused
  - Pickup reminder: sent from Scan Monitor to the guardians of students
                    still inside (single or bulk, manual or automatic)
  - Passwords     : parents, teachers and staff receive their password by SMS
  - In-app notifications are also shown to parents and teachers

14. NOTES AND TROUBLESHOOTING
================================================================================

  Blank pickup history
      No release has been scanned for that child, or the selected date /
      search has no matching record. The history never invents rows.

  Teacher sees no students
      A teacher's class = students whose adviser is that teacher OR whose
      grade/section matches the teacher's section. Re-saving the teacher
      re-links students of that section to them.

  Guardian cannot be scanned
      Check the QR code is registered under that parent or sub-fetcher and
      that the guardian exists in the Parents list.

  No SMS received
      Confirm the guardian's phone number, then check SMS Logs for the entry
      and its result.

  Release refused
      The day is closed, the time window has passed, or the child was already
      released in the current session.

  Forgot password
      Admin or staff can send a new password by SMS from the Parents,
      Teachers or Staff list.

  Duplicate ID
      Student / Parent / Teacher / Staff IDs must be unique. Leave the
      Teacher or Staff ID field blank to accept the next free number.

  Session expired
      Log in again; sessions expire after the configured lifetime.

  Camera not opening at the gate
      Browsers only expose the camera on https or localhost. Use
      http://localhost/... or serve the app over HTTPS.

================================================================================
 PROFILE PICTURES, QR FILES AND UPLOADS
================================================================================

Storage folders (all under public/uploads, mirrored to <project>/uploads):
    uploads/students/      {student_no}.jpg        e.g. 1234.jpg
    uploads/parents/       {parent_no}.jpg         e.g. P-1234.jpg
    uploads/teachers/      {teacher_no}.jpg        e.g. T-1001.jpg
    uploads/staffs/        {staff_no}.jpg          e.g. S-1002.jpg
    uploads/subfetchers/   {subfetcher_id}.jpg     e.g. 12.jpg
    uploads/qr/            {qr_code}.png           e.g. QR-KFJNY.png

Rules
 - Photos are square-cropped in the browser to 400x400 JPEG (q=0.9) before POST.
 - Saved server-side by app/Helpers/photo_helper.php (FCPATH . 'uploads/...').
 - Only JPG/JPEG/PNG/WEBP accepted; max upload guard applies.
 - A missing file is not an error: the UI falls back to an initials chip.

Where pictures can be set
 - Register page: student + parent avatars (Step 1 / Step 2).
 - Students list  -> 3-dot menu -> Edit (floating modal, picture + Delete picture)
 - Parents list   -> 3-dot menu -> Edit (floating modal, picture + Delete picture)
 - Teachers list  -> Edit modal (picture + Delete picture)
 - Staffs list    -> Edit modal (picture + Delete picture)
 - Sub-fetchers   -> add/edit modals inside the parent profile page.

Deployment note
 - If DocumentRoot is the PROJECT ROOT (not /public), the folder
   <project>/uploads must exist and resolve to public/uploads, e.g.
       mklink /J C:\xampp\htdocs\scan2fetch\uploads C:\xampp\htdocs\scan2fetch\public\uploads
   Without this link every /uploads/... URL returns 404 and QR codes /
   profile pictures do not display.
